# WordPress投稿フェーズ

下書きが完成した記事を WordPress に投稿するフェーズ。

## 前提

WordPress MCP サーバーが利用可能であること。
MCP ツール（`create_post` 等）が使えない場合は、[mcp-setup.md](mcp-setup.md) を参照してユーザーに設定を案内する。

## フロー概要

```
Step 1: 投稿前チェック — 機械チェック・機密情報チェック・アイキャッチ画像の確認
Step 2: カテゴリ・タグの選定 — WordPress の既存カテゴリ・タグから選定し提案
Step 3: 記事の投稿 — WordPress MCP で下書き投稿
Step 4: フェーズ完了確認 — 投稿結果を伝え posted へ
```

## Step 1: 投稿前チェック

### 機械チェック

まず機械チェックを実行する:

```bash
.agents/scripts/check-phase.sh <article-id> posted
```

このスクリプトは project.yaml への記事登録、draft.md の存在、本文が参照する画像の存在、textlint の合格を検証する（アイキャッチ画像がない場合は WARN が出るが、後続のステップで対応するため、ここでは合否に影響しない）。NG が出た場合は解消してから次に進む。

### 機密情報チェック

`blog/<article-id>/draft.md` を確認し、以下のような機密情報が含まれていないかチェックする:

- API キー、アクセストークン、シークレット
- パスワード、接続文字列
- AWS アカウント ID、ARN 等の内部識別子

プレースホルダー（`YOUR_API_KEY`、`xxxxxxxx` 等）は問題ない。
実際の値が含まれている場合は、ユーザーに報告し、プレースホルダーへの置換を提案する。

### アイキャッチ画像

`blog/<article-id>/images/eyecatch.png` が存在するか確認する。

チェック結果を以下のテンプレートで報告する:

**機密情報なし・アイキャッチあり:**

> WordPress 投稿フェーズです。投稿前のチェックを行いました。
>
> **機密情報チェック:** 問題ありませんでした。
> **アイキャッチ画像:** 確認済みです。
>
> 次にカテゴリとタグを選定します。

**機密情報なし・アイキャッチなし:**

> WordPress 投稿フェーズです。投稿前のチェックを行いました。
>
> **機密情報チェック:** 問題ありませんでした。
> **アイキャッチ画像:** 見つかりません。`/eyecatch` スキルでタイトルからアイキャッチ画像を生成できます。作成しますか？不要ならスキップします。

ユーザーがアイキャッチ作成を希望したら eyecatch スキルを実行する。スキップする場合はそのまま Step 2 へ。

## Step 2: カテゴリ・タグの選定

WordPress MCP でカテゴリ一覧・タグ一覧を取得し、記事に合うものを選んで提案する:

> WordPress の既存カテゴリ・タグを確認しました。
>
> - **カテゴリ**: （選定したカテゴリ）
> - **タグ**: （選定したタグ）
>
> （必要に応じて）「xxx」タグは存在しません。新規作成しますか？
> カテゴリ・タグを変更したい場合は教えてください。よければこの内容で投稿します。

## Step 3: 記事の投稿

ユーザーの合意を得たら、MCP の記事作成機能で投稿する。

投稿時のルール:

- ステータス: **draft**（下書き）で投稿する。公開はユーザーが手動で行う
- Markdown から Gutenberg ブロックへの変換は MCP サーバーが自動で行う
- 本文中の画像（`![alt](images/xxx.png)`）は MCP サーバーが自動でアップロード・URL置換するため、手動アップロードは不要
- アイキャッチ画像がある場合は `upload_media` でアップロードし、`featured_media` に media ID を指定する
- 外部リンクは URL をそのまま独立した段落に記述する（WordPress 側で自動的にカード形式で表示される）。`[blogcard url="..."]` 形式は使わないこと（Gutenberg 変換時にエスケープされて壊れるため）

## Step 4: フェーズ完了確認

投稿が完了したら、以下のテンプレートで報告する:

> 投稿しました。
>
> - **投稿URL**: （WordPress の投稿URL）
> - **ステータス**: 下書き（公開は WordPress 管理画面から行ってください）
>
> project.yaml を更新しました（phase: `posted`, wordpress_post_id: xxx）。
> WordPress 投稿フェーズはこれで完了です。

`project.yaml` の `phase` を `posted` に更新し、`wordpress_post_id` を記録する。

## phase 遷移条件

`posted` に遷移するには、以下がすべて満たされていること:

- `.agents/scripts/check-phase.sh <article-id> posted` が合格していること
- 機密情報チェックが完了し、問題がないこと
- WordPress に下書きとして投稿済みであること
- ユーザーに投稿 URL を伝えていること
